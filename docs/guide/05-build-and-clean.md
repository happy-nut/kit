# 변경을 만들고 diff 를 정리한다

만들기 플레이북들은 규율 하나를 함께 쓴다. 내가 본 것을 말하고, 증거는 플레이북이 요구하게 둔다. 이 장은 흔한 만들기 일마다 프롬프트에 무엇을 넣을지 보이고, 이어서 diff 를 리뷰할 수 있게 지키는 정리 습관을 다룬다.

## 만들기 플레이북마다 아는 것을 프롬프트에 넣는다

버그 프롬프트는 증상을 말하고 재현부터 하라고 한다.

```text
/dev:mode 이 명령이 재시도 뒤에 레코드를 두 개 내보내. 먼저 재현하고, 그다음 고치고 검증해.
```

기능 프롬프트는 동작과, 바뀌면 안 되는 것을 말한다.

```text
/dev:mode --json 플래그를 더해. 텍스트 출력은 바이트 하나까지 그대로야. 두 형식 다 검증해.
```

리팩터링 프롬프트는 구조를 옮기기 전에 동작을 고정한다.

```text
/dev:mode 파싱을 모듈 하나로 옮겨. 동작 변화는 없어야 해. 지금 출력을 먼저 기록하고, 옮긴 뒤에 그대로인지 증명해.
```

성능 프롬프트는 인상이 아니라 측정을 말한다.

```text
/dev:mode 이 픽스처에서 시작이 1.8초 걸려. trace 를 잡고, 잰 원인을 고치고, 전과 후를 보여 줘.
```

이 프롬프트들은 저마다 자기 플레이북으로 간다([버그 수정](../../skills/mode/playbooks/bug-fix.md), [기능](../../skills/mode/playbooks/feature.md), [리팩터링](../../skills/mode/playbooks/refactoring.md), [성능 문제](../../skills/mode/playbooks/perf-issue.md)). 플레이북이 내가 치지 않은 단계를 채운다. 고치기 전에 재현하고, 구현하기 전에 데이터 모양을 이름 짓고, 구조를 바꾸기 전에 동작을 고정하고, 최적화하기 전에 프로파일한다.

숫자 하나를 꾸준히 끌어올리는 일에는 [힐클라임 플레이북](../../skills/mode/playbooks/hillclimb.md)이 있다. 지표, 목표, 최소 시도 횟수를 주면 동결한 측정 하네스로 가설 하나씩 루프를 돈다. 이긴 것은 남기고 나머지는 모두 되돌린다.

두 성능 플레이북 모두 자기 숫자에 [`/dev:bench`](../../skills/bench/SKILL.md) 를 돌린다. 성능 문제 플레이북은 기준선과 그 뒤의 모든 숫자를 점검하고, 힐클라임 플레이북은 하네스를 동결하기 전에 점검한다. 언제 직접 치는지는 [검증하고 내보낸다](./06-verify-and-ship.md#잰-숫자는-devbench-로-점검한다)에 있다.

고치기 전에 원인부터 알고 싶을 때가 있다. 누수, 쉬는 중에 도는 CPU, 화면 글리치처럼 지금 살아 있는 증상이면 [런타임 포렌식 플레이북](../../skills/mode/playbooks/runtime-forensics.md)이 돌고 있는 프로세스를 계측한다. 이미 잡아 둔 프로파일이면 [트레이스 포렌식 플레이북](../../skills/mode/playbooks/trace-forensics.md)이 산출물을 읽고 뜨거운 프레임을 소스에 이어 붙인다. 둘 다 수정이 아니라 진단을 돌려준다.

```text
/dev:mode 느린 시작에서 잡은 cpuprofile 이야. 시간이 어디로 가는지, 어느 소스 줄이 그 시간을 쥐는지 알려 줘. 아직 고치지는 마.
```

## `/dev:tdd` 로 실패하는 테스트부터 쓴다

버그에 싼 로컬 테스트 경로가 있으면 프롬프트 전체가 두 낱말이어도 된다.

```text
/dev:tdd 구현해
```

맥락이 있으면 그걸로 충분하다. [`/dev:tdd`](../../skills/tdd/SKILL.md) 는 의도한 이유로 실패하는 가장 작은 테스트를 쓰고, 그다음 고치고, 테스트를 다시 돌린다. 테스트에 넓은 하네스 준비나 깨지기 쉬운 mock 이 필요하면 스킬이 그렇다고 말하고 가장 가까운 실행 검사를 대신 쓴다. 실제 명령이 더 강한 증거인 곳에 테스트를 억지로 넣지 않는다.

## TypeScript 규칙은 이름으로 불러 싣는다

[`/dev:ts`](../../skills/ts/SKILL.md) 는 타입 시스템 원칙을 구체 규칙으로 바꾼다. 판별 유니온, 경계에서는 `unknown`, 빠짐없는 변형 처리, 스키마에서 끌어낸 타입이다. 저절로 실리지 않으니 `.ts` 나 `.tsx` 파일을 건드리는 일이면 `/dev:ts` 를 친다.

## 커밋 전에 정리한다

[PR 열기 플레이북](../../skills/mode/playbooks/opening-a-pr.md)은 커밋마다 그 전에 diff 에 [`/dev:deslop`](../../skills/deslop/SKILL.md) 을 돌리고, `/dev:mode` 는 PR 설명과 커밋 본문에 [`/dev:unslop`](../../skills/unslop/SKILL.md) 을 적용한다. `/dev:deslop` 은 서술하는 주석, 근거 없는 방어 코드, `any` 캐스트, 깊은 중첩처럼 그 브랜치가 들여온 군더더기를 걷어 낸다.

글에는 `/dev:unslop` 에 대상과 덧붙일 규칙을 준다.

```text
/dev:unslop README 바뀐 부분, 긴 대시 없이
```

나만의 줄임말이 생길 것이다. 스킬은 `/dev:unslop 그거, 더 조여` 처럼 짧은 프롬프트에서도 의도를 잘 읽는다.

## `/dev:no-comments` 로 주석을 걷어 낸다

주석은 따로 한 번 훑어야 하고, 그 주석을 쓴 에이전트가 하면 안 된다. 작성자는 내가 내 주석을 지키듯 자기 주석을 지킨다. 그래서 리뷰 전에 새 눈에 넘긴다.

```text
/dev:no-comments diff
```

[`/dev:no-comments`](../../skills/no-comments/SKILL.md) 는 [`dev:comment-reviewer`](../../agents/comment-reviewer.md) 를 띄운다. 짧은 남길 목록을 가진 읽기 전용 리뷰어다. 남길 목록은 라이선스 헤더, 공개 API 의 doc 주석, 코드로 표현할 수 없는 것을 설명하는 링크, 우리가 바꿀 수 없는 외부 의존성이 강제하는 동작이다. 나머지는 모두 나간다. 우리 코드에서 놀라운 동작은 이 목록에 들지 않는다. 그 주석은 리팩터링 표시(`MUST KILL`)로 돌아오고, `/dev:no-comments` 는 받아들인 표시를 근본 원인에서 고친다. 주석이 「지우지 마」 같은 제약을 주장하면, 스킬은 그 주장을 타입, 테스트, 린트로 굳히자고 제안한다. 어느 쪽이든 주석은 지운다.

일의 나눔을 분명히 해 두면 좋다. `/dev:deslop` 은 코드에서 군더더기를 걷고, `/dev:unslop` 은 글에서 걷고, `/dev:no-comments` 는 주석을 그것을 쓰지 않은 리뷰어에게 넘긴다.

**함정:** 정리는 선택인 마무리가 아니다. 서술 주석과 방어용 죽은 짐이 든 diff 는 리뷰어에게 덜 끝난 것으로 읽히고, 그 여분의 코드가 다음 버그가 숨는 자리다. diff 가 부풀어 보이면 리뷰가 지적한 뒤가 아니라 커밋하기 전에 `/dev:deslop` 을 친다.
