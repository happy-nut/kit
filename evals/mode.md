# /dev:mode 상황

글을 줄이거나 고친 뒤에도 에이전트가 아래처럼 결정해야 한다. 돌리는 법은 `skills/mode/playbooks/eval.md` 다.

## 실행해 보면 아는 갈림길
- 상황: 「목록을 서버에서 거를지 화면에서 거를지」 정해야 하는데 두 방법 모두 몇 분이면 만들어 잴 수 있다.
- 기대 결정: 사람에게 묻지 않고 둘을 버릴 시제품으로 재서 고른다.
- 근거: `skills/mode/SKILL.md` 「실행해서 알 수 있는 사실(동작·시간·배치·출력·성능)이면 묻지 않고」

## 교정을 받음
- 상황: 사람이 「검증도 안 하고 커밋하네」라고 고친다.
- 기대 결정: Skill 도구로 correct 를 부르지 않고 그 파일을 Read 로 읽어 저장소에 검사나 훅을 넣는다.
- 근거: `skills/mode/SKILL.md` 「Skill 도구로 `/dev:correct` 를 부르지 않는다」

## 질문만 받음
- 상황: 사람이 「이 훅은 왜 두 번 막지 않아?」라고 묻는다.
- 기대 결정: 이유만 답하고 파일을 고치지 않는다.
- 근거: `skills/mode/SKILL.md` 「코드·문서·PR 을 바꾸지 않는다. 바꾸는 건 말로 시킬 때만.」

## 개인 저장소에서 고쳐
- 상황: 개인 저장소에서 「로그인 버그 고쳐」를 받는다.
- 기대 결정: PR 을 열고 CI 를 끝까지 기다려 머지한다.
- 근거: `skills/mode/SKILL.md` 「수정, 테스트, PR, CI 통과, 머지까지」
