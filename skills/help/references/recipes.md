# 따라 쓸 프롬프트

진짜 경로, 스킬, 완료 확인으로 바꿔 쓴다. 말투는 편해도 된다.

## 이해하기

- `/dev:mode <스레드나 이슈> 읽어. 근본 문제를 네 말로, 쉬운 말로 다시 적어.`
- `/dev:mode <길고 어수선한 요청>. 시작 전에 목표·완료 판정·보여 줄 증거·이미 아는 것·진짜 제약으로 다시 세워 줘. 일은 하지 마.`
- `/dev:mode <증상> 이 왜 나는지 조사해. 아는 것, 쓴 데이터, 가장 그럴듯한 가설을 줘. 아직 코드 바꾸지 마.`
- `/dev:how 로 <하위 시스템> 을 이해하고, /dev:why 로 최근에 왜 깨졌는지 찾아.`
- `/dev:recall 지난주 <주제> 작업, 그다음 <이슈> 읽어.`
- `/dev:why 왜 <다른 방법> 말고 이렇게 구현했어? 무엇을 맞바꿨어?`
- `/dev:mode 이 브랜치 이어받아. 결정 기록을 읽고 끝난 걸 찾아서 이어 가. 끝난 일은 다시 하지 마.`

## 만들기

- 버그: `/dev:mode <증상>. 재현 먼저, 그다음 고치고 확인해.`
- 앱 버그: `/dev:mode /verify-<앱> 으로 재현해. main 에서 재현되면 고치고 증거로 화면을 찍어 보여 줘.`
- 싼 테스트가 있는 버그: `/dev:mode <버그> 재현 먼저. 싼 테스트 길이 있으면 /dev:tdd 로. 그다음 고치고 다시 돌려.`
- 기능: `/dev:mode <동작> 추가해. <지금 출력> 은 바이트 하나 안 바뀌어야 해. 둘 다 확인해.`
- 리팩터링: `/dev:mode <코드> 를 한 모듈로 옮겨. 동작 변화 0. 지금 출력을 먼저 기록하고 나중에 같다는 걸 증명해.`
- 성능: `/dev:mode <작업> 이 <픽스처> 에서 <시간> 걸려. 트레이스 잡고, 측정된 원인을 고치고, 전후를 보여 줘.`

## 설계와 계획

- `/dev:mode <기능> 의 시제품을 몇 가지 만들어. 비교하게 스크린샷이나 영상 찍어 줘.`
- `/dev:mode <기능> 이 필요해. 먼저 /dev:design 으로 설계하고, 열린 질문은 시제품으로 답해. 구현 전에 보여 줘.`
- `/dev:mode <새 패키지> 를 내가 어떻게 쓸지 튜토리얼부터 써. 그다음 지금 것보다 왜 나은지 /dev:why 로 가르쳐 줘.`
- `이 스레드와 우리 접근에 대해 /dev:design 으로 다른 의견을 받아 줘.`
- `/dev:mode 이 설계를 계획으로 바꿔. 작고 검증 가능한 PR 들, PR 마다 자기 검증 단계.`
- `/dev:mode <라이브러리> 를 <대상> 으로 옮기는 계획. 작고 검증 가능한 PR 들. 결과는 버그까지 원본과 똑같아야 해.`

## 리뷰와 내보내기

- `/dev:review 브랜치 전체를 의심하면서. 아직 아무것도 바꾸지 마. 진짜 버그나 회귀가 아니면 잔소리는 빼.` 버린 목록도 읽는다.
- `/dev:formal-setup <모듈> 에서 <단계들> 이 엇갈리거나 재시도돼도 <속성> 이 성립함을 증명해.` 그 코드에 머지나 리팩터링이 있은 뒤에는 `/dev:formal-setup 다시 맞춰.`
- `/dev:swarm <폴더> 아래 패키지마다 자기 check 스크립트로 검사해. 패키지 하나에 워커 하나. 보고서 하나.`
- `/dev:mode PR 열어. 작고 순서 있는 커밋, 설명에 증거.`
- `/dev:mode 이 PR 돌봐. 초록으로 만들어.` 상태만: `/dev:mode PR <번호> 확인해. 남은 거 있어?`
- `/dev:mode 스택 내보내.`

## 비웠다 돌아오기

- `/dev:mode 자러 간다. <기준> 에서 새 워크트리로 <목표>. 됐다는 건 <확인들>. 결정 기록 남겨. 커밋 전에 묻지 마. 끝날 때까지 /loop. 몇 시간 해도 정말 막히면 멈추고 왜인지 적어.`
- `/dev:log 어젯밤 한 일 따라잡게 해 줘.` 주의할 것 절을 먼저 읽는다.
- `/dev:catchup` 은 내 마지막 메시지 뒤로 이 대화에서 일어난 일과 나를 기다리는 결정을 모두 준다.
- `/dev:mode 이 큐 끝까지 오토파일럿. 항목은 서로 독립이야.`
- `/dev:mode 이 변경들 오토파일럿, 머지는 하지 마. 내가 넣을게.`
- `/dev:reflect 배운 걸 남겨서 다음 실행이 되풀이하지 않게.` 앞으로의 결정을 바꾸는 수정만 승인한다.
- `/dev:correct <지적>` 은 같은 실수를 이 저장소의 구조·검사·훅으로 막는다.
- 방금 답이 어려우면 `쉬운 말로 다시 해 줘.`
