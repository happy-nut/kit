# Log

정본 기록은 하나만 둔다.

## 형식

TSV 파일 하나, 결정 하나에 한 줄. 셀은 한 줄로 남는다. 근거는 글이 아니라 가리키는 곳이다.

새 기록은 `references/decision-log-template.tsv`(헤더 한 줄)를 복사해 시작하거나, 아래 스크립트가 첫 호출에 헤더를 쓰게 둔다. 열:

- **ts.** ISO8601 시각.
- **phase.** 단계나 작업 줄기.
- **decision.** 고르거나 한 것, 한 줄.
- **why.** 이유를 쉬운 말로. 원칙 때문이면 꼬리표가 아니라 말로 쓴다.
- **evidence.** 그것을 증명하는 링크나 경로. 커밋 SHA, PR 번호, `파일:줄`, 산출물·트레이스·스크린샷 경로. 문단을 쓰지 않는다.
- **result.** 결과나 판정 상태: `tests green`, `reverted`, `pixel-diff 0`, `INCONCLUSIVE`, `open`.

리뷰어가 한눈에 읽게 쉬운 말로 쓴 예:

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	일의 크기부터 셌다. 컴포넌트 약 100개, 약 75시간	긴 실행 전에 크기를 알고 싶었다	commit 3a9f1c2	시작 전에 정할 것 5개를 찾았다
2026-05-24T09:40:00Z	harness	바꾸기 전에 옛 버전 스크린샷을 찍었다	옛것과 새것을 비교해 화면 변화를 잡으려고	snapshot.sh, baseline/	기준 스크린샷 120장 저장
2026-05-24T11:15:00Z	widget	위젯 스타일을 겉모습 그대로 옮겼다	변경을 작게, 결과를 똑같게	commit 7c21e0a, pixel-diff 0	똑같아 보임, 테스트 통과
2026-05-24T12:30:00Z	widget	도우미 작업을 버렸다. 스크린샷이 비어 있었다	요약을 믿지 않고 실제 파일을 확인했다	worktree reset	되돌림, 다음을 위해 지시를 좁힘
```

## 한 줄 쓰기

동료에게 무엇을 했는지 말하듯 쓴다. 쉬운 말, 구체 행동, AI 말투와 추상 용어 없이 쓴다. 기록 글에도 /dev:write 가 적용된다.

도우미를 쓴다.

```bash
<이 스킬 폴더>/scripts/log.sh <기록 파일> <phase> <decision> <why> <evidence> <result>
```

`ts` 를 UTC 로 찍고, 첫 사용에 헤더를 쓰고, 셀 속 탭·줄바꿈을 공백으로 바꾸고, `=`, `+`, `-`, `@` 로 시작하는 셀 앞에 작은따옴표를 붙인다. 인자가 6개가 아니면 종료 코드 1로 끝난다. `printf` 로 직접 한 줄을 붙여도 되지만, 셀이 생성된 글이나 사용자가 준 글에서 오면 같은 바이트를 조심한다.

모든 행동이 아니라 결정 지점과 확인 지점만 적는다: 고른 갈림길, 검증 결과와 함께 끝난 단위, 방향 전환이나 되돌림과 그 계기, 드러난 막힘, 고친 관문. 반복 실행이면 반복마다 한 줄. 사소하고 뻔한 것은 건너뛴다.

실행 하나는 에이전트 대화 하나다. 그 대화의 뒤 턴과 그 대화의 요약까지 포함한다. 이어받기, 대신 들어온 에이전트, 새 대화는 새 실행이다. 이미 행이 있는 기록에 쓰는 실행은 첫 행의 phase 를 `start` 로 한다. 다른 실행의 `start` 행 뒤에 쓰는 첫 행도 `start` 다. 그래서 뒤 턴에 기록으로 돌아온 실행은 먼저 마지막 행들을 읽어 그사이 다른 실행이 썼는지 본다. `start` 행은 이 실행이 쓰지 않은 앞 행들의 `ts` 범위를 적고, evidence 에 이 실행을 가리키는 것(세션 UUID, 에이전트 id)을 적는다. `start` 는 다른 데 쓰지 않는다.

## 두는 곳

기본은 커밋하지 않는 작업 산출물이다. 작업 폴더의 `decisions.tsv` 에 두고, 여러 작업이 동시에 돌면 `.audit/<작업 이름>.tsv` 에 둔다. git 에 넣지 않는다(`.git/info/exclude` 에 적는다).

리뷰어가 결과를 믿는 데 기록이 필요할 만큼 큰 일일 때만 커밋한다.

## 규칙

- 덧붙이기만 한다. 틀린 결정은 그것을 대신하는 새 행으로 고친다. 기록을 고치거나 지우지 않는다.
- 일회용 손 명령보다 커밋된 스크립트가 만든 근거를 쓴다. 「principles.md 의 Encode Lessons in Structure」(경로 `../mode/principles.md`)대로다.

## 기록을 대화와 맞춰 보기

실행이 끝나 넘기기 전에 기록이 사실을 말했는지 확인한다. 이 실행의 대화 기록을 읽는다. 위치는 `~/.claude/projects/<경로>/<세션>.jsonl` 이고, `<경로>` 는 현재 작업 폴더의 절대 경로에서 `/` 와 `.` 을 `-` 로 바꾼 것이다. 현재 작업 폴더의 것만 읽는다. `~/.claude/projects/*/` 를 통째로 훑지 않는다. 다른 프로젝트의 사적인 대화를 읽게 된다.

이 실행의 구간은 이 실행의 `start` 행(이 실행이 기록을 만들었으면 첫 행)에서 시작해 다른 실행의 다음 `start` 행 앞에서 끝난다. 그 구간의 행을 실제로 일어난 일과 맞춰 본다.

- 행마다 실제 결정이나 행동에 닿는지 본다.
- 행마다 근거가 열리고, 행이 주장하는 것을 보여 주는지 본다.
- 일을 바꾼 갈림길, 방향 전환, 버린 접근이 기록에 없으면 빈틈이다. 더한다.

이야기가 아니라 기록을 고친다. 지어낸 행이라도 이 확인은 행을 고치거나 지우지 않는다. 행이 실제 결정도 실제 행동도 아니거나, 주장이나 근거가 틀렸으면 실제로 일어난 일과 열리는 근거를 적은 새 행으로 대신한다. 이 확인은 이 실행 구간 밖의 행은 보지 않는다. 이 실행의 일이 그중 하나가 틀렸다고 보여 주면 틀린 결정처럼 새 행으로 대신한다.

## 다른 모델의 기록 검토

넘기기 전에 일을 한 모델과 다른 모델로 서브에이전트를 띄운다. 스스로 검토하는 것은 대신이 못 된다. 내가 `opus` 면 `fable`, `fable` 이면 `opus` 를 쓴다(`Agent`, `subagent_type: "general-purpose"`, 브리프에 「파일을 고치지 마라」). 같은 회사 모델이라 다양성이 약하다는 것을 보고에 적는다. 서브에이전트는 결정 기록과 이 실행의 대화 기록을 읽고 사용자가 눈여겨볼 것을 짚는다. 일을 다시 하는 게 아니라 아쉽거나 위험한 것을 훑는다.

- 근거가 약하거나 없는 결정.
- 건너뛰었거나 대화 기록에 증거 없이 주장한 검증.
- 지나고 보니 위험한 선택(이른 결정, 범위 넓히기, 증상 덮기).
- 대충 훑으면 사용자가 놓칠 빈틈.

기록을 남긴 실행의 답장은 늘 「주의」 절로 끝난다. 첫 줄에 검토한 모델을 따로 쓴다(`검토: <모델>`). 그다음 짚은 것마다 해당 행이나 순간을 가리킨다. 「짚을 것 없음」도 된다. 모델 이름은 빠지면 안 된다.

## 기록 읽기

위에서 아래로 읽고, 근거를 따라가고, 몇 개를 골라 확인한다. GitHub 은 커밋된 TSV 를 표로 보여 준다. 터미널에서는 `column -s$'\t' -t decisions.tsv`.

## 다른 스킬에서 쓰기

다른 스킬은 기록을 따로 만들지 않고 이 스킬로 보낸다. 이름(/dev:log)으로 가리키고 형식은 이 스킬에 맡긴다. 열 이름을 다시 쓰지 않는다.
