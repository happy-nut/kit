# 자율 실행

**언제.** 긴 일 하나를 멈추지 않고 끝까지 몬다(「끝날 때까지 돌려」, 「/loop X 될 때까지」, 「자고 올게」). 여러 날짜리 PR 대기열은 `autopilot-full.md`·`autopilot-stack.md` 다.

**소유.** 종료 조건을 소유한다. 끝을 정하고, 멈추지 않고 그리로 몬다.

## 단계

0. 돌리기 전에 이 저장소가 믿을 만한지 본다.
   셋 다 맞아야 돈다. 같은 종류의 일을 에이전트 하나가 사람의 고침 없이 끝낸 적이 있다. 종료 조건을 기계가 판정할 검증 장치(테스트, `verify-<앱>` 스킬, 검사 스크립트)가 있다. 결과를 산출물(스크린샷, 실측, 로그)로 볼 수 있다. 하나라도 없으면 자율로 돌리지 않는다. 그 기초를 먼저 만들고(`/dev:verify-setup`, 테스트, 린트) 보고한다. 안쪽 루프가 slop 을 내면 자동화는 slop 을 더 낼 뿐이다.
1. 첫 반복 전에 종료 조건을 확인 가능한 술어로 적는다.
   테스트 초록, 재현 해결, PR N 개 모두 머지, 픽셀 차이 0 같은 것. 「4시간 일해」 같은 시간은 종료 조건이 아니다. 시간만큼의 움직임만 남는다.
2. 깨우는 장치를 고른다.
   지켜볼 사건(CI, 머지, ref 전진)이 있으면 그 사건에 깨우는 감시를 건다. `gh pr checks <pr> --watch` 같은 명령을 Bash `run_in_background: true` 로 걸거나, 감시 서브에이전트(`subagent_type: "dev:worker"`, `model: "sonnet"`, `run_in_background: true`)를 띄운다. 그리고 긴 시간 간격 심장박동을 대비로 둔다. 사건이 없으면 결과를 다시 볼 만한 간격으로 정한 고정 심장박동을 쓴다. 심장박동은 Claude Code `/loop` 스킬이나 ScheduleWakeup 이다.
3. 반복마다 증거가 정당화하는 가장 작은 변경을 하고, 술어로 검증하고, 나아졌으면 커밋하고, 돕지 않은 변경은 버린다.
   「도움이 될지도」 싶은 이중 안전장치는 되돌린다. 남겨 두지 않는다. principles.md 의 Sequence Work into Verifiable Units 대로, 확인을 끝에 몰지 말고 단위마다 검증한 뒤 다음으로 간다.
4. 도중에 발견한 것이 목표를 돕는다면 직접 처리한다.
   망가진 스킬, 관련 버그, 불안정한 검증기, 리뷰 잡음, 도구 실패, 버려진 후속, 고칠 수 있는 드리프트를 `/dev:mode` 로 직접 고친다. 본류 밖 수정은 따로 PR 을 낸다. 되돌릴 수 있는 일을 사람에게 미루지 않고 `AskUserQuestion` 도 쓰지 않는다. 올리는 것은 되돌릴 수 없는 행동, 실험으로 정할 수 없는 진짜 제품·취향 결정, 진짜 막다른 길뿐이다. 술어를 본 동력으로 두고, 곁가지를 고칠 때마다 술어로 돌아간다.
5. 반복마다 `/dev:log` 로 체크포인트를 남긴다.
   무엇이 바뀌었고 술어가 움직였는지 한 줄.
6. 술어가 충족되면 멈춘다.
   정체는 멈춤이 아니다. 계속 가면서 접근을 바꿔 넘는다. 진짜 막다른 길이면 맴돌지 말고 올린다. 이기려고 술어를 느슨하게 하지 않는다.

## 답변에 넣을 것

- 종료 조건, 돈 반복 수.
- 무엇이 착지했고 무엇을 버렸는지.
- 마지막 술어 상태.
