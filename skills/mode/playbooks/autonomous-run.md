# 자율 실행

**종료 조건을 소유한다. 끝을 정하고, 멈추지 않고 그리로 몬다.**

1. 첫 반복 전에 종료 조건을 확인할 수 있는 술어로 적는다(테스트 초록, 재현 해결, PR N 개 모두 머지, 픽셀 차이 0).
2. Claude Code `/loop` 스킬로 깨우는 장치를 고른다. 지켜볼 사건(CI, 머지, ref 전진)이 있으면 그 사건에 깨워 주는 감시 서브에이전트를 두고, 긴 시간 간격 심장박동을 대비로 둔다. 사건이 없으면 결과를 다시 볼 만한 때에 맞춘 고정 간격 심장박동을 둔다. 서브에이전트마다 추론 수준을 일에 맞게 `/dev:mode` 「서브에이전트」 절대로 고른다.
3. 반복마다 증거가 정당화하는 가장 작은 변경을 하고, 술어로 검증하고, 나아졌으면 커밋하고, 돕지 않은 변경은 버린다. 「도움이 될지도」 싶은 이중 안전장치는 되돌린다. 남겨 두지 않는다.
   principles.md 의 Sequence Work into Verifiable Units 대로 일의 순서를 짠다. 확인을 끝에 몰지 말고 단위마다 검증한 뒤 다음으로 간다.
4. 도중에 발견한 것이 목표를 돕는다면 네 일이다. 망가진 스킬, 관련 버그, 불안정한 검증기, 리뷰 잡음, 도구 실패, 버려진 후속, 고칠 수 있는 드리프트를 `/dev:mode` 로 직접 처리한다. 본류 밖 수정은 따로 PR 을 낸다. 되돌릴 수 있는 일을 사람에게 미루지 않고 `AskUserQuestion` 도 쓰지 않는다. 올리는 것은 되돌릴 수 없는 행동, 어떤 실험으로도 정할 수 없는 진짜 제품·취향 결정, 진짜 막다른 길뿐이다. 술어를 본 동력으로 두고, 곁가지를 고칠 때마다 술어로 돌아간다.
5. 반복마다 `/dev:log` 로 체크포인트를 남긴다. 무엇이 바뀌었고 술어가 움직였는지 한 줄이다.
6. 술어가 충족되면 멈춘다. 정체는 멈춤이 아니니 계속 가면서 접근을 바꿔 넘는다. 진짜 막다른 길이면 맴돌지 말고 올린다. 이기려고 술어를 느슨하게 하지 않는다.

**답:** 종료 조건, 돈 반복 수, 무엇이 착지했는지, 무엇을 버렸는지, 마지막 술어 상태.
