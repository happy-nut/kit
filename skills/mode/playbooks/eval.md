# 평가

**실험 설계를 소유한다. 계획하고, 가리고, 돌리고, 종합한다.**

**가리기에서 양보하지 않는 것:**

- 후보가 보는 디렉터리, 파일, 프롬프트 어디에도 `eval`, `test`, `judge`, `experiment`, `rubric`, `score`, `compare`, `benchmark`, `candidate`, `arena` 를 쓰지 않는다.
- 후보 프롬프트는 자연스러운 사용자 요청처럼 보여야 한다. 목표를 말하고 메타는 말하지 않는다.
- 사슬을 끌어내는 단서를 주지 않는다. 어떤 스킬, 원칙, 파일을 썼는지 나열하라고 하지 않는다. 설계 메모는 일반적으로 묻고, 사슬을 따랐는지는 자기 보고가 아니라 코드 모양으로 채점한다.
- 디렉터리와 slug 이름을 정화한다. 사용자가 고를 법한 프로젝트다운 이름을 쓴다.
- 다른 후보가 있다는 것을 후보에게 알리지 않는다.
- 심판은 자기가 심판인 줄 알아도 되지만, 출력은 정화된 라벨로만 보고 모델 이름은 보지 않는다.
- 두 변형을 비교할 때는 심판 한 명이 두 묶음을 한 번에, 한 척도로, 어느 묶음이 어디서 왔는지 모른 채 채점한다.

**단계:**

1. **틀 잡기.** 시험할 변형과 성공으로 칠 행동을 적는다. 심판만 볼 채점 기준(구체 기준 3~6개)을 쓴다. 후보에게는 보이지 않는다.
2. **정화된 환경 만들기.** 후보마다 변형이 들어간 작업 디렉터리를 둔다. 자연스러운 작업이라면 있을 맥락(프로젝트 골격, 후보가 자연스럽게 읽을 스킬)을 심어 둔다.
3. **자연스러운 프롬프트 하나 쓰기.** 사용자가 칠 법한 말. 무엇을 재는지 새지 않게 한다.
4. **후보 N 개를 병렬로 띄우기.** `/dev:design` 의 「2. Fan out」 대로 후보마다 다른 모델로 띄운다. 각자 자기 정화된 디렉터리에서 일한다. 프롬프트는 모두 같다. 서브에이전트마다 일에 맞는 수준을 `/dev:mode` 「서브에이전트」 절대로 고른다. 띄우고, 확인하고, 결과를 모으기만 하는 에이전트는 `opus medium` 으로 돈다.
5. **가린 심판 한 명 띄우기.** `/dev:design` 의 「3. Cross-judge」 대로 다른 모델 계열로 띄운다. 심판은 정화된 라벨과 채점 기준만 보고 모델 이름은 보지 않는다.
6. **사슬은 자기 보고가 아니라 기록으로 검증하기.** 후보마다 현재 작업 폴더의 기록 `~/.claude/projects/<slug>/` 를 읽는다. slug 는 작업 폴더 경로의 `/` 와 `.` 을 `-` 로 바꾼 것이고, 이 세션의 `.jsonl` 옆 `<세션>/subagents/` 에 서브에이전트 기록이 있다. `~/.claude/projects/*/` 를 통째로 glob 하지 않는다. 작업 공간 경계를 넘어 상관없는 프로젝트의 사적 대화를 읽게 된다. 후보마다 실제로 연 파일을 본다. 사슬을 따랐는지는 실제로 읽은 파일과 코드 모양으로 채점한다. 후보 자신의 주장으로 채점하지 않는다.
7. **모든 후보 출력을 직접 끝까지 읽기.** 심판 판정과 비교한다. 어긋나면 모델이 치우쳤거나 채점 기준이 모호한 것이다. 종합한다.

**답:** 시험한 변형, 채점 기준, 후보별 메모, 심판 판정, 직접 읽고 낸 종합, 변형을 승격할지에 대한 추천.
