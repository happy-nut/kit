# 조사

**답을 소유한다. 계획하고, 길을 정하고, 쓴다.**

조사 요청은 읽기 전용이다. 결과는 근거를 단 설명이나 추천이지 코드 변경이 아니다.

1. 질문이 가리키는 코드를 추적한다. 동기를 묻는 질문이면 `/dev:why` 도 거친다.
2. 처리량 점검은 한 줄로 둔다. `처리량 점검: n/a, 읽기 전용 조사`.
3. 산출물(개요 / 핵심 개념 / 동작 방식 / 위치 / 함정)을 쓴다. 요청이 대안 사이의 결정이면 트레이드오프 표를 단 추천을 쓴다.
4. 답에 `/dev:write` 를 적용한다.

PR, PR 돌보기, `/dev:design` 은 없다. 조사가 코드 변경에 앞서는 일이면 예외다. 그때는 사용자에게 넘기고 `playbooks/bug-fix.md` 나 `playbooks/feature.md` 로 다시 고른다.

**답:** 조사 산출물. 「확실한가」류 답에는 이유를 붙인 진짜 판단을 넣는다. 전제가 틀렸으면 반박한다(mode 「자율」 절).
