# 런타임 포렌식

**진단을 소유한다. 소스로 이론을 세우지 말고 살아 있는 프로세스를 계측한다.** 산출물은 근거를 단 진단이지 수정이 아니다.

1. 맞는 표면에서 조종 스킬(`/dev:control-ui` 나 `/dev:control-cli`)로 실제 신호를 잡는다. 회전하는 프로세스는 CPU 프로파일, 누수는 힙 스냅샷, 화면 글리치는 CDP trace. 짐작이 아니라 실제 산출물이다.
2. 산출물을 결정적 증거로 줄인다. 뜨거운 경로의 함수, 새는 객체에서 GC 루트까지의 보유 사슬, 입력 없이 도는 루프. 큰 산출물은 서브에이전트에서 파싱하고(principles.md 의 Guard the Context Window), 줄인 결과는 본 스레드에 둔다. 서브에이전트마다 mode 「서브에이전트」 절대로 일에 맞는 추론 수준을 고른다.
3. 믿기 전에 메커니즘을 증명한다. 돌고 있는 프로세스에 CDP eval 로 계측을 넣거나, 리로드 없이 라이브 코드를 고쳐 가설을 싸게 확인한다.
4. 결과를 소스로 매핑한다. 파일, 심볼, 할당하거나 예약하는 줄.
5. 처리량 점검은 한 줄로 둔다. `처리량 점검: n/a, 읽기 전용 포렌식`.

**답:** 잡은 신호, 줄인 결과, 메커니즘을 증명한 방법, 소스 위치, 산출물 경로. 요청이 없으면 수정하지 않는다. 원인이 나오면 `playbooks/bug-fix.md` 나 `playbooks/perf-issue.md` 로 넘긴다.
