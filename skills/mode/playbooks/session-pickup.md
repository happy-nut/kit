# 세션 이어받기

**재개 지점을 소유한다. 앞 기록을 읽고, 다시 하지 않는다.**

1. 앞 기록을 찾는다. 현재 작업 폴더의 대화 기록(`~/.claude/projects/<작업 폴더 경로의 / 와 . 을 - 로>/<세션>.jsonl`. `~/.claude/projects/*/` 를 통째로 glob 하지 않는다. 작업 폴더 경계를 넘어 관계없는 프로젝트의 사적인 대화를 읽게 된다), 다른 워크트리, push 된 브랜치 중 하나다. 메타데이터 개요와 마지막 메시지를 먼저 읽고, 거슬러 올라가며 결정 지점을 훑는다. 긴 기록은 서브에이전트에서 파싱하고 줄인 타임라인만 본 스레드에 둔다(principles.md 의 Guard the Context Window). 서브에이전트마다 추론 수준을 일에 맞게 `/dev:mode` 「서브에이전트」 절대로 고른다.
2. 작업 상태를 재구성한다. 브랜치와 워크트리, 이미 착지한 것(`git log`, base 대비 `git diff`), 열린 할 일, 내려진 결정. 앞 기록은 권위 있는 입력이다. 다시 도출하고 싶은 쏠림을 누른다.
3. 끝난 것과 남은 것을 비교한다. 출시된 것과 계획된 것을 대어 재개 지점을 이름 짓고, 앞의 재현을 다시 돌리거나 끝난 일을 다시 하지 않는다. 「처음부터 다시 확인해 보자」는 권위 있는 기록을 믿을 수 없는 것으로 다룬다는 뜻이다.
4. 남은 일을 맞는 플레이북으로 보내고 판정을 고른다. 실행을 이어 가기, 끝난 권고를 내보내기, 앞 결론을 승인하거나 뒤집기, 실패한 실행의 사후 분석 중 하나다. 이 플레이북은 여기서 끝난다. 보낸 플레이북이 나머지를 맡는다.
5. 물려받은 주장을 원래 목표에 대어 실제 산출물에서 검증한다(principles.md 의 Prove It Works). 앞 에이전트의 통과 자기 보고는 증명이 아니다.

**답:** 앞 에이전트가 어디서 멈췄는지, 물려받은 것과 다시 한 것(다시 한 것은 없는 것이 이상적), 재개 지점, 결과.
