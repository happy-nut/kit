# 리뷰 봇 코멘트 분류

`../playbooks/babysit.md` 가 리뷰 봇이나 리뷰 자동화의 코멘트를 다룰 때 쓴다. 목표는 봇을 기본으로 무시하는 것이 아니다. 모든 코멘트를 꼭 고쳐야 할 코드 변경으로 다루지 않는 것이다.

## 판단 기준

행동하기 전에 스레드마다 분류한다.

- `fix`: 그럴듯한 정확성, 보안, 프라이버시, 데이터 손실, 인증, 결제, 마이그레이션, 멱등성, 경쟁 상태, 출시 동작 문제를 짚는다. 그 코드를 소유한 가장 아래 PR 에서 고치고, 커밋 SHA 로 답하고, 스레드를 닫는다.
- `dismiss`: 문서화된 저위험 잡음 패턴과 맞고, 지금 코드와 맥락이 코드 변경이 필요 없음을 증명한다. 짧은 이유로 답하고 스레드를 닫는다.
- `ask`: 새롭거나, 심각도가 높거나, 보안·프라이버시·데이터 관련이거나, 모호하다. 짐작하지 말고 사용자에게 묻는다.

모르겠으면 묻는다. 잡음 같은 코드 품질 코멘트를 넘기는 것은 싸다. 진짜 데이터·보안 버그를 넘기는 것은 싸지 않다.

## 배운 패턴 형식

새 패턴은 이 모양으로 더한다.

```markdown
### <짧은 패턴 이름>

- 확신도: candidate | recurring | strong
- 넘길 때: <모두 참이어야 하는 조건>
- 넘기지 않을 때: <위험 경계>
- 알아보는 신호: <패턴을 알아보게 하는 문구나 코드 맥락>
- 출처: <PR·코멘트 URL 이나 짧은 이력 메모>
```

예가 한두 개면 `candidate`. 실제로 여러 번 닫았으면 `recurring`. 패턴이 좁고, 여러 번 검증됐고, 저위험일 때만 `strong`.

## 자주 넘기는 후보

### 의도된 UI·디자인 시스템 시각 변경

- 확신도: candidate
- 넘길 때: PR 설명, 스크린샷, 디자인 리뷰, 근처 코드가 시각 변경을 명시하고, 코멘트는 공용 시각 기본값이 바뀌었다는 말을 되풀이할 뿐이다.
- 넘기지 않을 때: 접근성, 포커스 표시, 키보드 이동, 색 대비, PR 이 일부러 바꾸지 않은 컴포넌트 API 계약을 짚는다.
- 알아보는 신호: 포커스 외곽선, 버튼 크기, 간격, 공용 컴포넌트 시각 기본값에 대한 코멘트에 소유자가 「의도한 것」이라고 답한 경우.

### 위쪽 스택에서 쓰는데 리뷰어가 못 본 것

- 확신도: candidate
- 넘길 때: export, 컴포넌트, 헬퍼, 파일이 안 쓰인다고 짚었는데, PR 목록과 diff, 위쪽 스택 diff, PR 맥락이 스택의 뒤 PR 에서 쓰인다는 것을 보여 준다.
- 넘기지 않을 때: 이 PR 이 스택이 아니거나, 그 심볼이 공개 API 이거나, 위쪽 사용을 확인할 수 없다.
- 알아보는 신호: 「export 한 컴포넌트가 안 쓰인다」에 사람이 「위에서 씀」이라고 답한 경우.

### 병렬 구현 중의 일시 중복

- 확신도: candidate
- 넘길 때: PR 이 지우거나, 바꾸거나, 증명 중인 옛 경로와 나란히 새 경로를 두려고 적은 양의 코드를 일부러 복제한다.
- 넘기지 않을 때: 복제된 코드가 보안, 결제, 데이터 접근, API 동작을 바꾸거나, 오래갈 공용 추상화가 위험을 분명히 줄인다.
- 알아보는 신호: 「상당한 중복」, 「검증 로직 중복」에 소유자가 옛 경로를 지울 것이라거나 중복이 일부러 국소적이라고 설명한 경우.

### 기존 프레임워크·컴포넌트 불변식이 이미 막는 경고

- 확신도: candidate
- 넘길 때: 걱정하는 것이 공용 컴포넌트, 프레임워크 계약, 타입 불변식, 단일 정본으로 이미 보장되고 그것이 지금 diff 나 근처 코드에 보인다.
- 넘기지 않을 때: 불변식이 가정될 뿐 강제되지 않거나, 시점에 기대거나, 값이 갈라질 수 있는 비동기·상태 경계를 넘는다.
- 알아보는 신호: 공용 팝오버가 뷰포트 경계를 강제하는데 안쪽 팝오버에 max-height 가 없다는 코멘트, 또는 지역에서 확인한 값과 넘기는 값이 같은 출처인데 nullable 을 짚는 코멘트.

### 소유자가 밝힌 후속·미룬 정리

- 확신도: candidate
- 넘길 때: PR 소유자가 알려진 후속이라고 명시했고, 지금 PR 이 그 동작을 더 나쁘게 하지 않고, 고위험 영역이 아니다.
- 넘기지 않을 때: 에이전트가 소유자 말 없이 판단하거나, 중간·높은 심각도의 제품 동작이거나, 미루면 새 회귀가 머지된다.
- 알아보는 신호: 「그건 나중에 볼게」, 「언젠가 지울 거야」.

### 스스로 철회했거나 명시적 오탐인 규칙 코멘트

- 확신도: recurring
- 넘길 때: 코멘트 본문이나 뒤의 봇 답글이 지적을 철회했거나, 규칙을 지킨다거나, 오탐이라고 명시하고, 에이전트가 그 규칙을 로컬에서 확인할 수 있다.
- 넘기지 않을 때: 고위험 지적에 사람이 설명 없이 「오탐」이라고만 한 것이 유일한 증거다.
- 알아보는 신호: 파일 이름 규칙 코멘트 본문이 그 파일이 이미 규칙을 지킨다고 말하는 경우.

## 기본은 묻기

이전 PR 에서 비슷한 것을 닫았더라도 아래는 자동으로 넘기지 않는다.

- 보안, 프라이버시, 인증, 결제, 데이터 보존, 학습 데이터, 권한 경계 지적.
- 심각도가 높은 지적.
- 마이그레이션, 스키마, 멱등성, 동시성, 시스템 간 동작 지적.
- 제안한 수정이 작고 제품 의도를 바꾸지 않으면서 위험을 분명히 줄이는 코멘트.

과거 데이터에서 사람이 보안·데이터 흐름 코멘트를 닫은 적이 있다. 그것은 소유자의 판단이지 팀 전체의 넘기기 규칙이 아니다.

## 최근 babysit 에서 나온 후보

babysit 중이나 뒤에 팀에 쓸모 있어 보이지만 아직 무르익지 않은 배움을 여기에 더한다. 여러 PR 이 패턴을 확인하면 위 절로 올린다.

### 네이티브 브라우저 동작을 손으로 다시 구현한 코드

- 확신도: candidate
- 넘길 때: 거의 없다. diff 가 네이티브 브라우저 동작을 손으로 만든 것으로 바꾸면(네이티브 sticky 를 JS 로 위치 잡는 복제본으로, 네이티브 스크롤 대상을 전달한 wheel·touch 이벤트로, 그리기 순서 가림을 mask·clip-path 로) 그 코드에 대한 리뷰 봇의 로직 버그 지적은 꾸준히 진짜였다.
- 넘기지 않을 때: 이벤트 전달 빈틈(wheel deltaMode, 터치 팬, 가장자리 스크롤 체이닝, 탭 여유), mask·clip 의 hit-testing 차이, 그런 코드의 observer 와 React 상태 시점 경쟁을 짚는다. 기본은 fix.
- 알아보는 신호: 「mask 는 hit-testing 에 영향을 주지 않는다」, 「오버레이가 wheel 스크롤을 막는다」, 「deltaMode 를 무시한다」, 「React 가 상태를 적용하기 전에 IntersectionObserver 콜백에서 돈다」.
- 출처: sticky 가림 PR 하나. 봇 패스 여섯 번, 지적 약 18건, 하나도 닫지 않고 전부 고쳤다.

### 계약 시험 드리프트 주장은 싸게 확인된다. 시험부터 돌린다

- 확신도: candidate
- 넘길 때: 확인 자체는 절대 넘기지 않는다. 명령 하나면 된다. PR 이 프로토콜이나 문서 글을 고정하는 계약 시험(SKILL.md 위의 정규식, 문서 문구 스냅숏)을 싣고 리뷰어가 「시험이 문서와 더는 안 맞는다」(또는 그 반대)고 하면, 분류 전에 PR 끝에서 그 시험을 돌린다. 빨간색이면 주장이 실제로 맞다. 초록이면 닫는 답글의 구체적 반증이다.
- 넘기지 않을 때: 해당 없음. 이것은 닫기 패턴이 아니라 확인 지름길이다. 「반복 패스면 닫는 쪽으로 기운다」는 휴리스틱이 여기서는 틀린다. 글을 고정하는 시험은 앞 회차 수정이 글을 고치기 때문에 드리프트한다.
- 알아보는 신호: 앞 수정 커밋이 고정된 구절을 고쳐 쓴 PR 에서 「계약 시험이 수정 전 대기를 빠뜨렸다」는 지적. PR 끝에서 돌린 시험이 바로 그 단언에서 실패했다.
- 출처: 글을 고정하는 PR 하나, 봇 패스 여덟 번. 앞 패스가 모두 고치고 닫혔는데도 일곱 번째 패스의 주장은 진짜였다.

### 같은 PR 뒤 커밋에서 이미 고친 낡은 보안 리뷰 지적

- 확신도: candidate
- 넘길 때: 자동 보안 리뷰 같은 것이 인가·검증 호출이 빠졌다고 하는데, 지금 PR 끝이 바로 그 관문을 (시험과 함께) 분명히 갖고 있다. 보통 리뷰가 돈 뒤의 강화 커밋에서 들어간 것이다.
- 넘기지 않을 때: 인용한 헬퍼가 논의 중인 주체에게는 아무것도 하지 않거나, 확인이 지키려는 부수 효과 뒤에 돌거나, 그 주체에 대한 시험이 없다.
- 알아보는 신호: 정확한 관문이 PR 끝에서 부수 효과 전에 이미 불리는데 「인가 확인 누락」 HIGH 지적이 남아 있다.
- 출처: 강화 커밋이 리뷰 실행보다 뒤인 웹훅 엔드포인트 PR 하나.

### 일부러 좁힌 오류 조건을 넓히면 진짜 오류를 가린다

- 확신도: candidate
- 넘길 때: 좁은 오류 조건(특정 `errno`, 오류 코드, 상태 계열)을 전부 받는 것으로 넓히라는 지적이고, 그 좁음이 진짜 구분을 담는다. 전형은 `ENOENT` 에 묶인 의존성 대체 경로다. 「바이너리가 설치되지 않았다」와 「명령이 돌았고 실패했다」는 다른 상황이다. 0 이 아닌 모든 종료에 재시도하면 정당한 실패(없음, 만료된 인증, 네트워크)를 대체 경로로 다시 돌리고 대체 경로의 오류를 보고해 진짜 오류를 가린다.
- 넘기지 않을 때: 좁은 조건이 같은 범주의 경우(`EACCES` 같은 다른 「바이너리를 못 씀」 errno, 다른 전송 계층 실패)를 놓치거나, 처리 안 된 경로가 데이터를 잃거나 반쯤 된 상태를 남기거나, 재시도가 멱등이면서 원래 오류도 드러난다.
- 알아보는 신호: 대체 경로가 실패한 작업이 아니라 빠진 의존성 때문에 있는 코드에 대해 「X 가 ENOENT 로 실패할 때만 재시도한다 … 동작하는 Y 가 있어도 대체 경로를 시도하지 않는다」.
- 출처: 대체 경로가 실패한 명령이 아니라 빠진 바이너리 때문에 있는 CLI 이름 바꾸기 PR 하나.
