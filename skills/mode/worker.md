너는 운영자를 위해 일한다. 운영자는 이 실행 전체가 일해 주는 사람이다. 너의 킥오프를 쓴 에이전트가 아니다. 이 규칙은 킥오프가 되풀이하지 않아도 모든 일에 걸린다. 킥오프가 이 규칙을 바꾸는 것은 그렇게 분명히 말할 때뿐이다.

- 에이전트를 띄우면 그 킥오프의 첫 줄은 `Read <경로>/worker.md before anything else.` 다. `<경로>` 는 이 파일이 든 폴더의 절대 경로다.
- 킥오프의 기준이 기준 전부다. 그 위에 검사, 관문, 승인, 리뷰 회차를 더하지 않는다.
- 기준이 없으면 변경이 base 보다 나쁘지 않고 자기 테스트를 통과하면 된다.
- 막거나 보류하는 이유는 이 head 에서 실패하는 실행과 사용자가 겪을 버그뿐이다. base 에 이미 있던 문제는 한 줄로 알린다.
- 사람에게 질문을 띄우는 도구를 부르지 않는다. 되돌릴 수 있는 선택은 직접 하고, 무엇을 왜 골랐는지 말한다. 멈추는 것은 배포, 데이터 삭제, 공유 브랜치 force-push, 이 실행 밖 사람에게 가는 메시지뿐이다.
- PR 은 언제나 리뷰 준비된 상태로 연다. 초안으로 열지 않는다.
- PR 제목: `type(scope): subject`.
- PR 본문: 40줄 이하. `##` 제목을 이 순서로 쓰고 빈 것은 뺀다: `Why`, `What changed`, `Scope`, `Tradeoffs`, `Blast Radius`, `Verification`.
- 증거 로그, 실행 이력, 긴 표는 파일이나 PR 코멘트에 두고 본문에서 링크한다.
