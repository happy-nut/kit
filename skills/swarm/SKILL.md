# 스웜

`/dev:arena` 와 달리 결과를 하나로 합성하지 않는다. 덮기(coverage)나 경주(race)의 결과를 모아 보고한다.

## 시작

세션의 작업 목록 도구(데스크톱 앱이면 update_plan, 아니면 TodoWrite)에 단계마다 한 줄씩 열고 나서 띄운다.

1. Frame
2. Fan out
3. Aggregate
4. Report

## A. Frame

1. 완료 조건과, 스웜이 돌려줄 산출물이나 보고서를 적는다.
2. 모양을 고른다. 조각으로 나누기(slices), 같은 브리프로 워커 N개 경주(race), 또는 둘을 섞기. 경주나 혼합이면 띄우기 전에 선정 규칙을 선언한다. `first pass`(처음 통과한 것), `rank all`(모두 순위), `best-of`(가장 좋은 것) 가운데 하나.
3. 워커 모델을 고른다. `~/.claude/rules/dev-models.md` 의 `swarm workers` 줄, 없으면 `opus high` 다. 경주나 비교가 팔(arm)마다 다른 모델을 정할 때만 바꾼다. `Agent` 가 모델을 거부하면 `/dev:mode` 「서브에이전트」 절의 물러나는 순서를 따르고 그렇게 말한다.
4. 쓰는 워커에게는 각자 쓸 수 있는 출력 위치를 준다. 워커가 커밋을 검증하거나 측정하면 브리프에 정확한 SHA 를 적는다. 측정 브리프에는 방법(표본 수, 표본 하나가 무엇인지, 순서)도 적는다. 워커는 결과에 SHA 와 방법을 둘 다 기록한다. 측정은 `/dev:bench` 기준을 따른다.

## B. Fan out

N개를 한 메시지에서 모두 띄운다. 각 호출은 `subagent_type: "dev:worker"`, `isolation: "worktree"`, `run_in_background: true`, 그리고 3번의 `model`.

`isolation` 은 워커가 이 컴퓨터의 작업 폴더 상태 그대로(커밋하지 않은 변경, 돌고 있는 서버, 로컬 데이터)를 봐야 할 때만 뺀다. 그때는 워커끼리 같은 파일을 쓰지 않게 출력 위치를 나눈다.

워커가 기본 브랜치가 아닌 브랜치에서 시작해야 하면 브리프 첫 단계에 `git checkout <브랜치>` 를 적는다. 그 브랜치가 원격에만 있으면 `git fetch` 부터 적는다.

브리프는 하나하나 따로 서야 한다. 목표, 범위, 맡은 조각이나 경주 팔, 검증 방법, 보고할 것을 담는다. 보고는 `PASS`, `ISSUES`, `BLOCKED` 가운데 하나와 증거다. 결함을 증명할 수 있는 워커는 `ISSUES` 를 내고, 처음 것만이 아니라 증명할 수 있는 결함을 전부 적는다.

결과 없이 떨어진 워커가 있으면 N-1 개로 진행하고 그 사실을 적는다.

## C. Aggregate

끝난 결과를 읽는다. 브리프가 요구한 SHA 와 방법을 기록하지 않은 결과는 버리고 그 워커만 한 번 다시 띄운다. 두 번째에도 빠지면 빈칸(gap)으로 기록한다. 빈칸은 통과로 치지 않는다. 덮기면 필요한 조각마다 결과가 있어야 한다. 경주면 미리 선언한 선정 규칙(first pass, rank all, best-of)을 적용한다. 워커의 원시 출력을 그대로 붙이지 않는다.

워커가 고쳤다고 한 것은 diff 를 직접 보고 확인한다. 워커의 요약을 그대로 옮기지 않는다.

쓰지 않는 워커 worktree 와 브랜치는 지운다.

## D. Report

대화 안에 보고서 하나로 돌려준다.

- 결과 표 (조각이나 팔마다 판정, 근거, SHA)
- 결함 한 줄씩
- 빈칸과 탈락
- 경주였으면 적용한 선정 규칙
