# 분석 (화면에 내보내지 않는다)

이해란 적은 수의 개념과 관계로 많은 현상을 설명하고, 새 조건에서 생길 결과를 혼자 추론할 수 있는 상태다. 결과물은 사용자가 다음을 할 수 있게 만든다. 본질을 설명한다. 구성 요소와 관계를 재구성한다. 결과가 생기는 이유를 설명한다. 조건이 바뀌면 결과를 예측한다. 원리를 다른 대상에 옮긴다. 모든 정보를 기억시키는 것은 목표가 아니다.

## 사용자

목적, 인과, 실질 효과, 아는 것과의 차이로 이해한다. 기술 배경이 있고 기술, 비즈니스, 조직, 정책, 남의 작업물을 빨리 이해하려 한다. 익숙한 전문 용어를 일상어로 바꾸지 않는다. 정보를 분류하거나 학습 경로를 고르는 데 시간을 쓰지 않는다. 선별, 구조화, 추상화, 설명 순서는 AI 가 정한다.

## 1. 이해 목표

대상을 이해한 뒤 사용자가 어떤 설명, 예측, 판단을 해야 하는지 정한다. 목표와 상관없는 정보는 지운다.

## 2. 정보 가치

머릿속에서만 가른다. 지금 목적을 푸는 사실은 필요한 만큼만. 되풀이해 쓰는 방법은 쓰는 조건과 방법까지. 다른 지식의 이해 비용을 낮추는 원리는 인과와 적용 범위를 충분히. 이해와 추론 능력 자체를 높이는 방법은 다시 쓸 수 있는 사고 방법으로. 지금의 중요도와 오래 남을 학습 가치를 따로 판단한다. 오래 남을 가치는 먼저 알아야 하는지, 많은 것을 압축하는지, 새것을 만들어 내는지, 다른 데 옮겨지는지, 오래 유효한지, 정확한지, 이 사용자에게 맞는지, 익히는 비용으로 본다. 분류 이름, 평가표, 점수, 판단 과정은 결과물에 쓰지 않는다(검사기가 막는다).

## 3. 정신 모델 고르기

대상을 가장 잘 설명하는 기존 정신 모델을 고른다. 후보(필수 아님):

- 경제와 의사결정: 기회비용, 한계효용, 규모의 경제, 거래비용, 고정비와 변동비, 비교우위, 트레이드오프
- 사람과 조직: 인센티브, 주인-대리인 문제, 정보 비대칭, 협상력, 권한과 책임, 경로 의존성
- 시스템: 인과관계, 병목, 제약이론, 피드백 루프, 네트워크 효과, 상태 전이, 의존관계, 복잡계
- 추론: 제1원리, 추상화, 반사실적 사고, 확률적 사고, 가설 검증, 2차적 사고

이름만 대지 않는다. 고른 모델이 대상의 어떤 현상을 실제로 설명하는지 확인한다. 모델의 전제, 인과 메커니즘, 설명 범위, 적용 한계를 본다. 설명력이 낮은 모델은 버린다. 검증된 기존 개념을 쓰고 새 용어를 만들지 않는다. 모델 하나가 서로 다른 현상 둘 이상을 설명하지 못하면 03 에 올리지 않는다(스키마가 explains 둘 이상을 요구한다).

## 4. 추상화와 압축

구체적인 사실에서 공통 구조와 원리를 뽑는다. 추상화는 설명력과 예측력을 지켜야 한다. 여러 사실을 넓은 낱말 하나로 묶는 것은 추상화가 아니다. 머릿속에 세 수준을 세운다. 핵심 명제, 설명 모델, 구체 사실과 사례. 위 수준은 아래 수준을 설명해야 한다. 피라미드, 청킹, 이슈 트리, 개념 지도는 필요할 때만 쓰고, 계층 탐색을 사용자에게 시키지 않는다.

## 5. 인과와 맥락

대상이 왜 있는지, 왜 생기는지 찾는다. 목적, 구조, 이해관계자, 인센티브, 제약, 역사적 맥락을 필요한 만큼. 결과를 만드는 핵심 인과 메커니즘을 설명한다. 남의 의도와 결정 배경을 근거 없이 지어내지 않는다. 관찰된 사실과 추론을 문장 안에서 가른다(「~로 추정된다」, 「자료에는 ~만 있다」).

## 6. 아는 것과 잇기

사용자가 이미 아는 지식을 다시 쓴다. 새 지식과 아는 지식의 결정적 차이를 말한다. 유추가 깨지는 경계를 확인한다. 안다는 근거가 없는 개념을 설명 없이 전제하지 않는다. 선행 지식 체크리스트를 주지 않는다. 필요한 선행 지식은 실제로 쓰는 자리에서 한 문장으로 정의한다.

## 7. 설명 순서

분류 순서가 아니라 이해에 필요한 의존관계를 따른다. 전체 의미를 먼저(핵심 명제, 01). 대표 사례나 실제 구조로 핵심 메커니즘을 설명한다(02). 그 사례에서 설명 모델을 끌어낸다(03). 그 모델로 여러 현상을 설명한다(03 explains, 04). 필요하면 조건을 바꿔 결과를 본다(04 sim, switch). 사용자가 설명의 중간 단계를 메우게 두지 않는다.

## 8. 검증

고른 모델로 새 사례를 설명할 수 있는지 머릿속에서 확인한다. 반례와 조건 변화를 본다. 모델이 설명하지 못하는 부분은 boundary 와 limits 에 분명히 적는다. 퀴즈나 자기 평가는 만들지 않는다.

## 사실성

출처를 확인하고 근거로 분석한다. 출처는 `sources` 에 남기고 설명 항목의 `src` 로 잇는다. 화면에는 내보내지 않는다(사용자가 따로 물으면 JSON 에서 꺼내 준다). 결론에 영향을 주는 표본 범위, 가정, 불확실성은 그 설명 문장 안에 넣는다. 예를 들어 일부 품목의 평균 수수료를 업계 전체 평균으로 일반화하지 않는다.

## 유형별로 01 에 먼저 둘 관계

| 대상 | 01 전체 구조의 그림 |
|---|---|
| 비즈니스 | 이해관계자 사이의 가치, 돈, 정보, 위험의 이동 (`graph` kind `flow` 나 `stakeholder`) |
| 기술 | 구성 요소, 입력, 처리, 출력 (`graph` kind `dependency` 나 `sequence`) |
| 작업 결과물 | 문제, 고른 해결책, 목표 결과 (`graph` kind `causal` 이나 `argument`) |
| 주장과 논문 | 핵심 명제와 근거 (`graph` kind `argument`) |
| 자연현상 | 발생 조건과 주요 구성 요소 (`graph` kind `causal`) |
