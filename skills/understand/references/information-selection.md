# 정보 선별

이 문서의 분류와 평가는 머릿속에서만 쓴다. JSON 에도 HTML 에도 넣지 않는다. 분류표, 유형 이름, 점수, 배지는 화면에 나가지 않는다(`scripts/validate.py` 의 `INTERNAL` 이 막는다).

## 1. 정보의 네 유형

정보를 이 사용자와 지금 목적을 기준으로 나눈다.

- **소비재형.** 지금의 궁금증이나 결정을 푼다. 필요한 사실과 의미를 전한다. 오래 익힐 필요가 없다.
- **도구형.** 특정 업무나 문제에 되풀이해 쓴다. 쓰는 조건, 쓰는 법, 한계를 중심으로 다룬다. 필요할 때 찾아볼 수 있는 모양으로 둔다.
- **자본재형.** 다른 지식을 이해하는 비용을 낮춘다. 도메인의 핵심 전제, 구조, 인과, 다시 쓸 수 있는 원리다. 아는 것과 잇고, 적용 조건과 반례를 따진다. 사용자의 정신 모델에 들어가게 설명한다.
- **메타형.** 지식을 얻고, 짜고, 추론하고, 검증하는 능력 자체를 낫게 한다. 다시 쓸 수 있는 사고 절차로 바꾼다. 그 절차가 통하는 조건과 실패하는 조건을 말한다.

유형은 정보에 붙은 고정 속성이 아니다. 사용자가 이미 아는 것, 지금 목적, 앞으로의 일에 따라 바뀐다.

## 2. 복리 가치

자본재형과 메타형 정보의 가치를 아래 기준으로 판단한다.

- 선행성: 얼마나 많은 후속 지식의 전제가 되는가.
- 압축성: 얼마나 많은 사실을 원리 하나로 설명하는가.
- 생성성: 배우지 않은 지식을 스스로 끌어낼 수 있게 하는가.
- 전이성: 다른 문제와 도메인에도 쓸 수 있는가.
- 재사용 빈도: 앞으로 얼마나 자주 쓰는가.
- 지속성: 시간이 지나도 맞는가.
- 정확성: 현실을 정확히 설명하는가.
- 개인 적합성: 이 사용자의 앞으로의 학습과 일에 맞는가.
- 습득 비용: 이해하고 쓰는 데 얼마가 드는가.

복리 효과를 근거 없는 숫자로 적지 않는다. 추상화가 높다고 가치가 높은 것이 아니다. 한 도메인의 구체 사실도 많은 후속 지식의 전제가 되면 자본재 가치가 크다.

## 3. 지금 중요도와 오래 갈 가치는 따로 본다

- 소비재형이라도 지금 판단에 꼭 필요하면 먼저 설명한다.
- 자본재형이라도 지금 목적과 관련이 낮으면 `deep` 으로 내리거나 뺀다.

## 4. 설명 비용 나누기

유형과 중요도로 다음을 정한다.

| 정할 것 | JSON 에서 어디에 드러나나 |
|---|---|
| 설명할지 | 항목을 넣거나 뺀다 |
| 설명 순서 | 배열 순서 |
| 설명 깊이 | 문장 수, `detail` 개수 |
| 기본으로 보일지 | `depth` (`overview` · `standard` · `deep`) |
| 구체 사례가 필요한지 | `mechanism` 의 `example` 블록 |
| 반례 검증이 필요한지 | `limits` 의 `counterexample`, `scenario` |
| 오래 기억할 원리 | `principles` |

분류는 설명을 고르는 수단이다. 분류 자체를 사용자에게 전하지 않는다.

## 5. 기본 화면에 둘 것

다음 중 하나에 해당하는 정보만 `overview` 에 둔다. 나머지는 `standard`, `deep` 으로 내리거나 뺀다.

- 대상의 본질을 잡는 데 필요하다.
- 전체 구조를 잡는 데 필요하다.
- 핵심 인과를 설명하는 데 필요하다.
- 잘못된 이해나 판단을 막는다.
- 지금 이해의 병목을 없앤다.
- 앞으로의 학습 비용을 뜻있게 줄인다.

분량을 줄였다고 인지 비용이 준 것이 아니다. 필요한 인과를 빼서 사용자가 직접 추론하게 만들면 비용은 늘어난다.

인지 비용은 읽는 비용, 용어를 푸는 비용, 정보 사이 관계를 잡는 비용, 설명 구조를 잡는 비용, 아는 것과 잇는 비용, 잘못 이해한 것을 고치는 비용, 새 인터페이스에 익숙해지는 비용을 모두 포함한다.
