# 문체

명확하고, 짧고, 하나로만 읽히게 쓴다. 관제 통신이 그 기준이다. 관제 용어를 쓰라는 뜻은 아니다. 전달에 필요한 문장만 쓴다. 이 규칙은 `/dev:unslop` 위에 얹는다. 두 문서가 부딪히면 이 문서가 앞선다.

## 쓴다

- 결론을 먼저 쓴다.
- 한 문장에 명제 하나.
- 주체, 행위, 대상, 조건을 드러낸다.
- 같은 개념에는 같은 낱말을 끝까지 쓴다.
- 견줄 때는 무엇과 무엇을, 무슨 기준으로 견주는지 쓴다.
- 원인과 결과를 가른다.
- 사실과 추론을 가른다. 추론은 `status: "inference"` 로 표시한다.
- 전문용어는 꼭 필요할 때만, 처음 나올 때 정의한다.
- 대명사가 무엇을 가리키는지 흐리면 명사로 쓴다.
- 문장은 짧게. 그래도 필요한 논리 연결은 빼지 않는다.
- 불확실하면 무엇 때문에 불확실한지 쓴다.
- 숫자에는 단위와 비교 기준을 붙인다.
- 문장은 「-다」 로 끝낸다.

## 쓰지 않는다

수사 표현. 아래와 비슷한 말을 모두 포함한다. `scripts/validate.py` 의 `BANNED` 가 대표 표현을 막지만, 목록에 없는 비슷한 말도 쓰지 않는다.

- 네 가지 축에서 만납니다.
- 바로 그 갈래입니다.
- 핵심은 바로 여기에 있습니다.
- 이 지점에서 중요한 것은
- 단순히 A 를 넘어 B 로
- 새로운 패러다임
- 강력한 시너지
- 복잡한 퍼즐의 마지막 조각
- 본질을 관통하는 여정
- 흥미로운 지점
- 놀라운 통찰
- 진정한 의미에서
- 한 단계 더 나아가
- 가능성을 열어줍니다.
- A 와 B 가 맞닿아 있습니다.

그리고 뜻 없는 도입부, 사용자 칭찬, 감탄과 과장, 장식 은유, 추상적인 홍보 문구, 뜻 없는 동의어 바꾸기, 불필요한 영어 병기, 내용 없이 문장을 잇는 말, 되풀이되는 결론, 형식을 채우려는 설명, 이모지, 긴 대시(—).

## 고쳐 쓰기 예

| 쓰지 않는다 | 쓴다 |
|---|---|
| 이 네 가지 축은 결국 하나의 지점에서 만납니다. | 네 요소는 처리 비용을 줄이는 공통 목적을 가진다. |
| 바로 그 갈래에서 새로운 가능성이 열립니다. | 조건 A 가 채워지면 처리 방식 B 를 쓸 수 있다. |
| 이는 단순한 기술을 넘어 비즈니스 혁신의 핵심입니다. | 이 기술은 심사 시간을 줄인다. 실제 절감 효과는 검증이 필요하다. |
| 조직의 복잡한 이해관계가 하나의 축을 형성한다. | 운영팀은 처리 시간 단축을 원한다. 보안팀은 접근 권한 제한을 요구한다. |

## 문장 지우기 검사

문장마다 묻는다. 이 문장을 지우면 사용자의 이해, 예측, 판단에 필요한 정보가 사라지는가. 아니면 지운다. 필요한 맥락과 인과 연결까지 지우지는 않는다.

## 섹션마다 쓰는 법

| 섹션 | 쓰는 법 |
|---|---|
| 01 본질 | `definition` 은 본질을 바로 말하는 한 문장. `support` 는 존재 이유나 발생 원인, 왜 알아야 하는지를 세 문장 안에. 정의로 충분하면 `support` 를 비운다 |
| 02 전체 구조 | L1 은 본질의 핵심 명제(01 의 정의를 되풀이하지 않는다). L2 는 실제 관계(`relation`)에 맞게. 계층이 아니면 L3 를 비우고 `edges` 로 관계를 그린다 |
| 03 작동 원리 | 어떻게 성립하고 도는지. 정적인 대상은 구성 관계나 논리 구조. 그림이 글보다 어려우면 글 |
| 04 조건과 한계 | 잘못 적용하는 것을 막는 것만. 중요한 조건 변화가 있으면 `scenario` |
| 05 기억할 원리 | 하나에서 셋. 원리마다 성립 조건과 다른 상황의 구체 적용 예. 옮겨 쓸 원리가 없으면 `kind: "fact"` |

섹션끼리 같은 내용을 되풀이하지 않는다(`validate.py` 가 같은 문장을 막는다). 뜻있는 내용이 없는 섹션은 `{"na": "이유"}` 로 쓴다. 빈 표, 빈 그림, 뜻 없는 선택지를 만들지 않는다.

## 그림

그림은 관계를 잡는 비용을 줄일 때만 쓴다. 관계의 성격에 맞는 모양을 고른다.

- 계층: `structure` 의 사다리.
- 관계가 얽혔으면 `diagram`(되먹임 고리도 그린다).
- 시간 순서가 중요하면 `steps`.
- 견주기가 중요하면 같은 기준을 가진 `compare`.

선은 실제 관계일 때만 긋고 관계 이름을 붙인다. 근거 없는 그래프, 비율, 순위, 점수, 백분율을 만들지 않는다.
