# 문체, 시각화, 인터랙션

## 문체

항공 통신 수준의 명확성. 짧고 정확한 기술 문서 문체.

- 결론을 먼저 쓴다.
- 한 문장에 주요 명제 하나.
- 주체, 행위, 대상, 조건을 밝힌다.
- 같은 개념에는 같은 용어.
- 익숙한 전문 용어는 그대로. 새 전문 용어는 처음 쓰는 자리에서 정의한다.
- 인과의 중간 단계를 빼지 않는다.
- 사실과 추론을 가른다.
- 수치에는 단위와 범위를 쓴다.

모든 문장은 새 사실, 관계, 원인, 결과, 조건 가운데 하나 이상을 전한다. 아니면 지운다. 장식적 은유, 과장, 감탄, 홍보 문구, 쉬워 보이려는 용어 바꾸기를 쓰지 않는다. 표준 용어가 있으면 표준 용어를 쓴다.

금지 표현(검사기가 막는다): 「네 가지 축에서 만난다」, 「바로 그 갈래다」, 「본질을 관통한다」, 「가능성을 열어준다」, 「단순히 A를 넘어 B로」, 「새로운 패러다임」, 「시너지를 창출한다」, 「누가 아픈지로」, 「치르는 값」, 「보는 눈도 함께 밖으로 나간다」, 「사슬의 맨 끝에서 먹고산다」. 화면 조작을 말하는 글(누르다, 클릭, 더 보기, 고르면)도 쓰지 않는다. 화면은 설명만 담는다.

## 시각화

텍스트로 전하기 어려운 관계를 전할 때만 쓴다. 먼저 전할 관계를 정하고, 그다음 모양을 고른다.

| 전할 관계 | 컴포넌트 |
|---|---|
| 원인과 결과, 피드백 루프 | `graph` kind `causal` (되먹임 선은 옆으로 휘어 그린다) |
| 돈, 가치, 정보, 자원의 이동 | `graph` kind `flow` |
| 이해관계자 사이의 이해와 힘 | `graph` kind `stakeholder` |
| 구성 요소의 의존 | `graph` kind `dependency` |
| 상태 전이 | `graph` kind `state` (선 이름이 전이 조건) |
| 주장과 근거 | `graph` kind `argument` |
| 시간 순서로 주고받는 것 | `sequence` |
| 상대 크기와 비율 | `bars` (`unit`, `basis` 에 표본과 범위) |
| 실제 대안 사이의 차이 | `table` |
| 조건 변화에 따른 결과(계산 가능) | 04 의 `sim` |
| 조건 변화에 따른 결과(정성) | 04 의 `switch` |

그림은 전체와 부분, 원인과 결과, 시간에 따른 변화, 상대 크기와 비율, 자원·돈·정보의 이동, 상호작용과 피드백, 조건 변화의 결과, 대안 사이의 차이 가운데 하나 이상을 전해야 한다. 글을 상자에 넣어 잇는 것만으로는 시각화가 아니다. 화살표는 실제 관계이고 선마다 이름이 있다(스키마가 요구한다). 핵심 참여자를 빼지 않는다. 그림과 본문이 같은 것을 말하면 한쪽을 지운다. 그림을 읽으려고 따로 설명이 필요하면 구조를 줄인다. 그림을 지워도 이해 비용이 같으면 지운다. 피라미드와 트리를 모든 대상에 강제하지 않는다.

## 인터랙션

사용자의 추론을 도울 때만 만든다. 정보를 보려고 클릭하게 하지 않는다. 인터랙션이 없어도 기본 설명은 다 읽힌다(기본값의 결과가 처음부터 보인다).

허용: 변수 변경에 따른 결과 변화, 실제 대안 사이의 비교, 상태 변화 관찰, 인과관계 변화 관찰, 조건 변경에 따른 시스템 반응.

- 수학으로 나타낼 수 있는 관계는 `sim` 으로 실제 계산한다. 출력은 입력과 앞 출력의 식이다. 렌더러가 식을 미리 RPN 으로 옮기고 페이지는 그것만 계산한다.
- `share` 는 합이 전체가 되는 출력만 묶는다.
- `notes` 는 조건식이 참일 때만 보이는 정성적 결과다.
- 근거 없는 수치 모델을 만들지 않는다. 가정에 기댄 계산은 `assumption` 에 가정 모델임을 짧게 쓴다.
- 정량화할 수 없는 관계는 `switch` 로 조건과 결과, 이유를 쓴다.
- 인터랙션을 위한 인터랙션은 만들지 않는다.
