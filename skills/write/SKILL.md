# Write

피곤한 엔지니어가 처음 읽고 이해하게 쓴다.

- 일하지 않는 낱말은 모두 자른다.
- 짧고 흔한 낱말을 쓴다. 「활용한다」가 아니라 「쓴다」.
- 규칙이 문장을 망치면 다른 방법으로 고치거나 그냥 둔다.
- 심볼, 파일, 플래그, 명령은 동의어나 설명이 아니라 실제 이름으로 쓴다.
- 전문용어를 지어내지 않는다. 개발자가 소리 내어 말하는 낱말을 쓴다. 이름 붙은 패턴은 처음 나올 때 뜻을 말한다.

## 리듬을 섞는다

- 문장 길이를 섞는다. 생각 둘을 나르는 문장은 나눈다. 생각 하나를 나르는 긴 문장은 둔다.
- 설명 글에서는 견해를 갖는다. 참조 글은 건조하게 둔다.
- 구체적으로 쓴다. 「스키마 변경은 문제를 일으킬 수 있다」가 아니라 「컬럼 이름을 바꾸면 빌드가 깨진다」.

## 갈래부터 고른다 (Diátaxis)

문서 하나에 갈래 하나. 갈래를 섞지 않는다. 나누고 링크한다.

- **튜토리얼: 하면서 배우기.** 배우는 사람이 무엇을 만들지 말한다. 단계마다 눈에 보이는 결과가 나오고, 무엇이 보여야 하는지 말한다. 설명은 한 구절과 링크로 줄인다.
- **하우투: 목표까지의 단계.** 읽는 사람의 문제를 푼다. 실력을 전제한다. 행동만 쓴다. 갈림은 허용한다. 제목은 일 이름으로 짓는다.
- **참조: 찾아보는 사실.** 묘사만 한다. 건조하고, 빠짐없고, 확신 있게 쓴다. 묘사하는 대상의 구조를 닮게 짠다.
- **설명: 이해와 이유.** 경계가 있는 주제 하나. 맥락을 준다. 설계 결정, 역사, 제약, 대안이다. 의견은 여기서만 허용한다.

## 읽는 사람에게 문장을 쓴다 (Google developer style)

- 읽는 사람(영어면 "you")에게 현재형으로 말한다.
- 누가 무엇을 하는지 말한다. 피동은 행위자를 모르거나 요점과 상관없을 때만 쓴다.
- 지시는 명령으로 쓴다. 조건을 지시 앞에, 흔한 경우를 먼저 둔다.
- 유행어, 비유, 「부디」를 쓰지 않는다. 절차에 「그냥」, 「쉽게」, 「빠르게」를 절대 쓰지 않는다.
- 미리 알리지 않는다. 이어지는 문장을 같은 말로 시작하지 않는다.
- 링크 글은 어디로 가는지 말한다.
- 제목은 요점을 담는다. 영어 제목은 sentence case. 페이지당 h1 하나, 단계 건너뛰기 없음.
- 순서가 있으면 번호 목록, 나머지는 글머리. 목록은 완전한 문장으로 소개한다. 항목은 모양을 나란히 맞춘다.
- 코드는 코드 글꼴로, UI 요소는 굵게. 나열의 마지막 항목 앞에도 쉼표를 둔다. 「등」을 쓰지 않는다.

## 문장을 하나씩 싣는다 (STE 규칙)

- 문장 하나에 지시 하나. 다른 곳에서도 문장 하나에 생각 하나.
- 약 20어절이 넘는 지시와 약 25어절이 넘는 다른 문장은 나눈다.
- 경고나 조건은 그것이 지키는 단계 앞에 둔다.
- 조사를 빼지 않는다.
- 낱말마다 뜻 하나를 주고, 동작마다 낱말 하나를 고른다.
- 절차는 직접 명령으로 쓴다. 이야기나 피동으로 쓰지 않는다.
- 「~하기」, 「~함」 같은 명사형을 되도록 피한다. 영어면 "-ing" 낱말이다.

## 두 가지로 읽히는 문장을 남기지 않는다 (Global English)

- 「만」, 「안」 같은 말은 꾸미는 말 바로 옆에 둔다.
- 긴 명사 줄을 푼다.
- 「이것」, 「그것」, 「이」가 분명한 하나를 가리키게 한다. 「이」나 「이는」으로 앞 절 전체를 가리키지 않는다.
- 동사를 빼지 않는다. 「~라는」처럼 구조를 보여 주는 작은 말도 빼지 않는다.
- 헷갈릴 수 있으면 나열에서 조사를 되풀이한다. 「와」나 「또는」이 무엇을 잇는지 말한다.
- 쌍반점이나 긴 대시 대신 마침표를 쓴다. 빗금을 쓰지 않는다. 「파일(들)」을 쓰지 않는다. 괄호 안은 문법상 온전한 단위로 쓴다.
- 한 대상은 어디서나 이름 하나로 부른다.
- 관용구, 구어, 라틴 약어, 비유를 쓰지 않는다.

## 말투와 저장소

- 이 스킬이 손대는 모든 문서에 /dev:unslop 을 적용한다(`../unslop/SKILL.md` 를 Read 로 읽고 따른다). AI 티 목록(AI 상투어, 군더더기, 얼버무림, 서식 티)은 그 스킬이 맡는다.
- PR 설명과 커밋 메시지도 글이다. Diátaxis 를 뺀 모든 층이 적용된다. PR 본문은 리뷰어가 1분 안에 읽는 브리핑이다. 스웜 로그, SHA 목록, 지표 표를 붙이지 않는다. 링크한다.
- 제품 UI 문구는 문서가 아니다. 그것에는 제품의 문구 지침을 쓴다.
- 코드 조각은 탭으로 들여쓴다. 경로는 실제 경로로 쓴다. 개수나 트리를 주장하면 그것이 들어가는 커밋에서 참이어야 하고, 다시 만드는 명령을 함께 적는다.
